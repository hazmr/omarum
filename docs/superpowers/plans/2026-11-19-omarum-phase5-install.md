# Omarum Phase 5 (Real Install) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Omarum runs like a real Omarchy app. It starts at login (systemd user services), shows a button in the Omarchy bar, has an entry in the Omarchy menu and an app-launcher entry, installs with one command, uninstalls cleanly, and ships an AUR PKGBUILD (publishing it needs the owner's OK).

**Architecture:** Two user services: `omarum.service` (the daemon, which owns the ZONOS3 child) and `omarum-orb.service` (the overlay), both `PartOf=graphical-session.target`, modeled on the installed `superwhisper.service`. A Quickshell bar plugin (`bar/omarum/`) follows `omarum watch` (JSON lines) and acts through `omarum tap` / `omarum settings`. Integration edits (menu JSONC, desktop file, units) are generated by tested stdlib code in `omarum/integration.py`; `scripts/install.sh` / `scripts/uninstall.sh` call it.

**Tech Stack:** systemd user units, Quickshell/QML (Omarchy bar plugin API: `BarWidget`, `BarIconButton`, `Process` + `SplitParser`), Omarchy menu JSONC extensions, bash, uv.

**Spec:** `docs/superpowers/specs/2026-11-18-omarum-design.md` §7 (Omarchy integration), §9 step 5; owner requests: bar button, louder voice (done separately).

## Global Constraints

- Plugin id `omarum.panel`, folder `~/.config/omarchy/plugins/omarum` → symlink to the repo's `bar/omarum` (as Superwhisper does). Enabled with `omarchy plugin enable omarum.panel`; passes `omarchy plugin validate`.
- Bar button: an orb glyph; theme foreground when closed, accent (`activeColor`) when Rum is open; **left-click = tap** (hands-free on/off), **right-click = settings**; tooltip shows the state.
- Units live in `~/.config/systemd/user/`; `Restart=on-failure`, `RestartSec=2`, `UMask=0077`. The orb unit sets `Environment=LD_PRELOAD=/usr/lib/libgtk4-layer-shell.so`.
- The installer is idempotent and never overwrites other people's hooks, menu entries or bindings. The uninstaller removes only what Omarum added (data in `~/.local/share/omarum` is kept unless `--purge`).
- The spike's shell restart loop and `spike-install.sh` are retired.
- Publishing to the AUR is outward-facing: prepare the PKGBUILD, then **stop and ask the owner** before any push.
- No co-author trailers in commits.

## Review Focus

1. **The daemon is down** when the bar starts → the button shows "off", and `omarum watch` keeps retrying without spinning the CPU. (Task 1 test)
2. **Running the installer twice** → one menu entry, one hook, one `require`, units are not duplicated. (Task 3 tests)
3. **Uninstall** → Omarum's binds, hook, menu entry, units and plugin link are gone; nothing else is touched. (Task 3 test + manual)
4. **A tap from the bar while a session is starting** → no double start. (Task 1 test)
5. **After reboot / re-login**, Rum is ready without running anything. (Task 4 manual: `systemctl --user restart` simulation plus a check that the units are enabled)

### Task 1: `omarum tap` and `omarum watch`

**Files:** Modify `omarum/daemon.py`, `omarum/cli.py`, `omarum/ipc.py`; Test `tests/test_daemon.py`, `tests/test_ipc.py`

**Interfaces:**
- Daemon command `{"cmd":"tap"}` = `ptt.press(now)` then `ptt.release(now)` (zero duration, so it is always a tap) → hands-free on, or close.
- `ipc.watch(path, on_message, retry_secs=1.0, stop=None)`: connects, sends `status`, calls `on_message` for each state message (levels skipped), and on disconnect emits `{"type":"state","state":"off"}` then retries every `retry_secs` until `stop()` returns True.
- CLI `omarum watch`: prints one JSON line per state change (`{"state": "...", "reason"?: "..."}`), flushing each line; `omarum tap`.

- [ ] Failing tests: `test_tap_opens_hands_free_then_closes`; `test_tap_during_start_is_single_session` (two concurrent taps while the factory builds → one start); `test_watch_reports_off_then_reconnects` (no socket → `off` emitted; then start a hub → `idle` received; stop after it).
- [ ] RED → implement → GREEN (`uv run pytest -q`). Commit `feat: omarum tap and omarum watch`.

### Task 2: Bar button plugin

**Files:** Create `bar/omarum/manifest.json`, `bar/omarum/BarWidget.qml`, `bar/omarum/README.md`

**Interfaces:**
- Manifest: `schemaVersion 1`, `id "omarum.panel"`, `kinds ["bar-widget"]`, `entryPoints.barWidget "BarWidget.qml"`, `barWidget.defaultSection "right"`, `allowMultiple false`.
- QML: `BarWidget` with a `BarIconButton` (glyph `󰪥`, the circle; `active` while the state is not `idle`/`closed`/`off`); `Process` running `["omarum", "watch"]` with `SplitParser` → `root.state`; restarts 3 s after exit; left click → `bar.run("omarum tap")`; right click → `bar.run("omarum settings")`; tooltip `"Rum: " + label`.

- [ ] `omarchy plugin validate bar/omarum` → valid.
- [ ] Manual: link it into `~/.config/omarchy/plugins/omarum`, `omarchy plugin enable omarum.panel`, screenshot the bar idle and with a session open; left-click opens hands-free and right-click opens settings (via `hyprctl` cursor click if possible, otherwise via the commands).
- [ ] Commit `feat: Omarchy bar button`.

### Task 3: Integration code, installer, uninstaller

**Files:** Create `omarum/integration.py`, `packaging/systemd/omarum.service`, `packaging/systemd/omarum-orb.service`, `packaging/omarum.desktop`, `scripts/install.sh`, `scripts/uninstall.sh`; Delete `scripts/spike-install.sh`; Test `tests/test_integration.py`

**Interfaces:**
- `add_menu_entries(jsonc: str) -> str`: inserts, before the final `}`, an `"omarum"` submenu (`icon "󰪥"`, label `Omarum`) with `omarum.talk` (`omarum tap`), `omarum.settings` (`omarum settings`) and `omarum.restart` (`systemctl --user restart omarum omarum-orb`). Idempotent: already present → unchanged. Handles a trailing comma or no previous entries.
- `remove_menu_entries(jsonc: str) -> str`: removes exactly those lines.
- `render_unit(template: str, repo: Path, omarum_bin: str) -> str`: fills `@REPO@` and `@OMARUM@`.
- `remove_require(bindings_lua: str) -> str`: drops the Omarum `require` block added by `shortcuts.apply`.
- `install.sh`: `uv tool install --force --editable .`, models (Whisper base.en always, large-v3-turbo only if `nvidia-smi` sees a GPU, Kokoro) skipped when present, `omarum shortcuts`, theme hook, units → `systemctl --user daemon-reload && enable --now`, desktop file, menu entries, bar plugin link + enable, kills any leftover spike loop. ZONOS3 is optional: `--with-zonos3` builds it (CPU + Vulkan) as done in phase 1.
- `uninstall.sh [--purge]`: the reverse.

- [ ] Failing tests: `test_menu_entries_added_once`; `test_menu_entries_into_empty_extension_file`; `test_menu_entries_removed_cleanly`; `test_render_unit`; `test_remove_require_only_ours`.
- [ ] RED → implement → GREEN. `bash -n` both scripts.
- [ ] Commit `feat: installer, uninstaller, systemd units, menu and desktop entries`.

### Task 4: Switch this machine over and verify

- [ ] Stop the spike loop, run `scripts/install.sh`; `systemctl --user is-enabled omarum omarum-orb` → enabled; `is-active` → active; only one daemon and one ZONOS3 server.
- [ ] Simulate a crash (`kill -SEGV` on the daemon) → systemd restarts it within about 2 s.
